# Spec — AI for Executives: Session 0 and Session 1

Scope note: this spec covers **Session 0 and Session 1 only**, per the map's stated priority ("session one first, session two is a first draft"). Session 2's content (nutshell continuation, Lab 3/Aufbereiten, Lab 4/Hinterfragen, the scheduled-task agent demo, Skills) is real but provisional and is **not** specified here — it appears only as a locked/dimmed placeholder chapter, per the shell standard. Everything below is drawn from the resolved tickets in `.scratch/exec-learning-page/issues/` and the map (`.scratch/exec-learning-page/map.md`); ticket references are given inline so a reader can go to the source decision.

## Problem Statement

A senior executive who has only lightly poked at ChatGPT needs to go from "I have Claude installed" to knowing how to instruct it, spot where it genuinely helps in her own work, and walk away with a ranked list of use cases for her company — without ever being lectured at, without jargon that sounds like software, and without a session that only works while a facilitator is in the room.

The facilitator delivering this needs a single reusable artifact — not a slide deck, not a one-off document — that carries real teaching content, works identically live (parallel copies, voice-led, no screen share) and solo (reopened alone, a week later, with nobody to ask), and can be handed to a new client without a rewrite.

## Solution

A single self-contained HTML site (`prototypes/PROTOTYPE-nav-rail.html` is the shell reference), delivered as a hosted URL, built around one continuously scrolling page with scroll-snap — one teaching "beat" per full-viewport screen. The central metaphor governs every line of content: Claude is *the assistant you always wished for* — a capable, tireless, occasionally-confidently-wrong new colleague. Every limitation is taught as a mechanism of how the tool works, not excused as a quirk; every strength is framed as something to hand over.

The build has three chapters in scope here:

- **Session 0 — "Session 0 — wo stehen wir heute?"** A facilitator-led discovery conversation, folded into the front of Session 1 (no separate booking), producing a project-scoping one-pager: who she is, her AI maturity, her daily work, her goal for the engagement.
- **Session 1 — "Was kann das, und wie briefe ich es?"** Showcase → "AI in a nutshell" (four first principles) → the four-step vocabulary (Erklären / Aufsetzen / Aufbereiten / Hinterfragen) → Lab 1 (Erklären) → Lab 2 (Aufsetzen) → the use-case backlog and matrix, run 1.
- **Session 2 — locked.** Rendered as a dimmed, inert placeholder chapter behind a joke password gate (`askclaude`), unlocked only in the second of the project's two deploys.

The executive's copy is **read-only** end to end: she never types into the page itself. The facilitator captures on her behalf (backlog cards, Session 0 answers) while she talks and works live in her own Claude window, which the page never embeds. The one exception to "no input" is the backlog/matrix component, which is a single always-editable view the facilitator operates.

## Implementation Decisions

**Artifact and delivery**
- One self-contained HTML file (assets inlined, e.g. base64 for images), authored from multiple source files and built into that single output. This file is both the thing hosted and the thing handed over at the end of Session 2 as a permanent offline archive.
- Hosting: Netlify, one site per customer. Customer one uses a neutral `*.netlify.app` subdomain (no purchased domain yet); a shared owned domain with per-client subdomains is the longer-term direction, not built now.
- Exactly two deploys for the whole engagement, same URL both times: deploy 1 ships everything in this spec's scope (Session 0 + Session 1 real; Session 2 titled/placeholder, locked); deploy 2 (out of this spec's scope) ships Session 2's real content plus the executive's finished matrix baked into the HTML as a seed block. No further deploys after that — frozen per client, no back-porting content improvements to earlier clients.
- Gating is two hardcoded, non-persistent, joke passwords in one playful register, checked client-side only (no real auth, no backend): the front door (`doris` for this client — this variable per client) and the Session 2 unlock (`askclaude`). Neither gate persists across visits; both are decorative, not access control. The rule governing what's safe to bake into a decorative-gate page: nothing goes into the matrix seed that wouldn't be fine in an unencrypted email.
- The executive's copy never reads or writes browser storage anywhere on the page. The only exception in the reverse direction is the facilitator's own working use of `localStorage` during a live session (backlog/matrix, Session 0 capture) purely as a same-session convenience — never relied on to persist, since JSON export is the actual record of truth.

**Shell (applies to every chapter, including Session 0 and Session 1)**
- One continuously scrolling page, `scroll-snap-type: y mandatory` / `scroll-snap-stop: always`, one full-viewport beat per screen. No header bar, no separate navigation column, no divider lines, no page-level cards — a single fixed gradient background with rail, type, and menu floating transparently on top of it.
- Left position-only nav rail: closed state shows dots per beat (done / current / upcoming); hover expands 104px → 330px and pushes page content right (never overlays). Chapter = bare number + title; sub-chapters show only under the active chapter. Scroll-position tracking is computed from scroll offset, not `IntersectionObserver` (the latter doesn't fire reliably in a backgrounded tab); a zero-height-viewport guard prevents false resyncs.
- Keyboard navigation: arrow keys move to the adjacent beat, disabled while any input/textarea/contenteditable has focus.
- Top-right mark only: product name + current chapter label. No progress counter, no breadcrumb, no left-hand brand block.
- Two surfaces only, never a third: Papier `#F4F5F7` (gradient `#F9FAFC` → `#E7EBF4`) and Navy `#08102A` (depths `#16226B` / `#1B2A82`). Ink `#0A1330`. Accent Ultramarin `#1E2FDB` used only as accent/form, never as a full-bleed ground; Ultramarin tief `#1526A8` and Eisblau `#B3CCF4` / Eis-Tint `#E4EBFB` round out the palette. Dominant mode is ~75% Papier / ~25% Navy (inverted from the original brief's dark-dominant assumption, since this is read solo on a personal screen, not projected).
- Low-amplitude gradients throughout on both surfaces (no flat fields). Two glass registers (light glass on Papier, dark glass on Navy) used only for content components (panels, tree branches, capture cards) — never as page-level chrome.
- Typography: Archivo 800 (tracking `-0.036em`, line-height 1.00) for headlines, Inter for body text. Archivo's width axis held in reserve at width 88 as a documented per-page override for headlines carrying an unusually long compound word.
- Icons: Lucide only, stroke width 1.5, no fill, one family, never mixed with emoji — used as a consistent structural element (eyebrows, the four steps, panel labels, tree branches, capture field, buttons), not decoration.
- Illustration register (see ADR-0001 for full derivation): single-colour hand-drawn axonometric line drawings, generated via the `media-gen` skill only (never hand-authored SVG, never a placeholder that ships). Form/contour always `#1E2FDB`; fills only in `#B3CCF4` (never as contour); wherever white would sit, punch a transparent hole (`fill-rule="evenodd"`) instead of filling white. No cast shadows, no greys, no gradients inside the illustration itself, no texture. Exactly one exception: the opening hero may be a full-bleed image with its own ground. Subjects are the executive's own artifacts (a resolving spreadsheet, a rewritten email, folding meeting minutes), never generic AI iconography.
- Session 2's rail entry renders dimmed (34% opacity), `pointer-events: none`, labelled "Nach Session 1," with inert rail dots — until the `askclaude` gate is passed (which, per deploy 1, only ever reveals titles/placeholders, since Session 2's real content isn't shipped until deploy 2).

**Session 0 — "Session 0 — wo stehen wir heute?"**
- Its own top-level rail chapter, positioned before the Session 1 showcase; not folded into the showcase beat. No separate booking or time budget — runs as long as it takes at the front of Session 1's calendar slot.
- One card, "Ihr Profil," with four tabs: **Über Sie** (Vorname, Rolle/Position, Unternehmen, Webseite, Kurzbeschreibung Firma — each captured as a separate field), **AI Reifegrad**, **Ihr Arbeitsalltag**, **Ihr Ziel mit AI**.
- First name, role, and company echo live in the card header as the facilitator types them, so the card reads as an actual customer profile rather than a blank form.
- AI Reifegrad is a fixed, five-level ascending staircase control, same list for every client (not editable per client): Installiert, nicht im Alltag → Ad-hoc-Nutzung → Regelmäßig, aber ohne Methode → Bereits mit System → Power-User. Selecting a level shows only that level's description below (fade/lift-in), not a repeated title. This ladder is deliberately coarse (a few minutes of live placement) and is a separate artifact from the four-step vocabulary taught later — it does not pre-seed the backlog/matrix.
- Ihr Arbeitsalltag and Ihr Ziel mit AI each hold three fixed, individually-labelled questions with their own dedicated answer field (not a shared free-text box). Every answer field auto-formats as a bulleted list (starts with "• " on focus; Enter continues the list). Exact question wording (checked against published AI-readiness-assessment practice) is fixed in `issues/18-session-zero-whiteboard.md`, rounds 16–18.
- All executive-facing copy (tabs, ladder descriptions, questions) addresses her directly ("Sie"). The tool's own facilitator-facing chrome (lede line, staircase placeholder prompt) uses "du," since that's addressed to whoever is operating the input.
- A small, unobtrusive "Export JSON" control (bottom-right) downloads the complete captured state at any point (person fields, selected Reifegrad level + description, and every Arbeitsalltag/Ziel question-answer pair) — a safety net against a lost tab/refresh, not a synced or persisted store.
- Closes with a full-screen popup ("Das Ziel ist klar. Jetzt beginnt der Weg.") offering a primary action into Session 1 and a dismiss/back link; Escape also dismisses it.
- Input throughout is facilitator-only, matching the rest of the build — the executive's copy is read-only.

**Session 1 — "Was kann das, und wie briefe ich es?" (content authored to ~91–93 min against a 120-min hard ceiling; the two-hour booking is overrun buffer, never authored against)**

1. *Showcase — "Ein Protokoll, drei Empfänger"* (~3 min). Facilitator-driven, executive watches (the one point in either session where her hand is off the artifact, by deliberate design). Runs on a single real asset (`start demo/Unterlage/Protokoll Stiftungsratssitzung 11.06.2026.docx`) through three prompts in one conversation: (1) Essenz — five lines, decided vs. still open; (2) Mail an die Personalleiterin — three paragraphs, surfacing a buried deadline; (3) the same content rewritten for a different audience (Versicherte, ohne Fachbegriffe). Includes a ~20-second live fact-check of one number against the source document. Left unnamed in the moment; named retroactively at the four-steps beat as "das war Aufbereiten — nur eine Datei." Regie and verbatim prompts live in `start demo/REGIE-KARTE.md`.
2. *"AI in a nutshell"* (~46–48 min). A single section built around four researched first principles, not a topic list, in this order: (0) a short scene-setting intro tying back to the homepage subtitle and stating the central metaphor; (a) KI/ML/LLM container definitions; (b) Principle 1 — Context is king (working-memory analogy, context rot, worked example: verify one number at the source); (c) Principle 2 — confidently-wrong-as-mechanism (next-token prediction, why a confident wrong answer scored better in training than "I don't know"); (d) Principle 3 — brief it like a new colleague, worked example **"Ein besseres Briefing"**: one task ("eine Einladung zu einem internen Workshop schreiben") run four ways — faul, mit Kontext, mit Beispiel, Claude selbst um ein besseres Briefing bitten — closing line: *"Sie müssen die perfekte Anfrage nicht selbst kennen — fragen Sie danach."*; (e) Principle 4 — it's a product built on a model, not the model itself (base/fine-tuned/system-prompt/interface/tools layering; open- vs. closed-weight, vendor-neutral; an orchestrator example; one company, several surfaces); (f) Projekte in Claude as a workspace with its own memory (Skills explicitly excluded — moves entirely to Session 2, not even teased here); (g) "Gehört das überhaupt hierher?" — the three-branch decision tree (KI / Automatisierung / bleibt bei Ihnen), worked on the case of matching invoices against purchase orders, landing on the honest answer that this is *not* an AI case (AI enters one step later, at the follow-up email to the supplier).
3. *"Die vier Schritte"* (~10 min, theory/wrap-up). All four steps introduced and named by what the executive is holding when she starts: **Erklären** (nur ein Thema) → **Aufsetzen** (leeres Blatt) → **Aufbereiten** (etwas, aber in der falschen Form) → **Hinterfragen** (etwas Fertiges, das halten muss). Each carries its boundary and its Gegenmittel (see table below). Includes the one-line "loop" note — any of the four steps repeated becomes a process rather than a conversation — which is the bridge to automation, not a fifth category. Closes visibly with two steps (Aufbereiten, Hinterfragen) named but not yet practised — the deliberate, unresolved cliffhanger into Session 2.
4. *Lab 1 — Erklären* (~10 min). Default task: *"Erklären Sie mir Claude"*, run once lazy then once with an added lever of her choice. Always-visible open alternative: pick an unresolved question from the nutshell theory just covered and apply the same technique. Always-visible Beispiele list of five alternative topics, each with a form label and a copy-ready prompt (full set fixed in `issues/04-lab-set.md`). Five pre-populated lever prompts (Zielgruppe / Tiefe / Analogie / Format / Prüfbarkeit) apply on top of whichever topic was chosen. Ends on the citation check: verify one stated fact at its real source. Debrief: the one fixed capture question.
5. *Lab 2 — Aufsetzen* (~12 min). Default task: an Auftragsbestätigung email to a new client in her industry, including a rough cost estimate as plain inline text/table content (explicitly not a real spreadsheet — that would drift into Aufbereiten, out of scope for this lab). Always-visible open alternative: her own "blank page she's been avoiding," plus a Beispiele list of five alternative full tasks spanning format (email, document, agenda, an image brief — a written brief for an image tool, not a generated image, staying vendor-neutral — and a short speech). Five pre-populated lever prompts (Ton & Zielgruppe / Struktur / Rahmenbedingungen / Referenz / Abschluss). No in-session "save this as reusable" step — that mechanic was cut; the take-home handout carries the intersession assignment instead. Debrief: the one fixed capture question.
6. *Board, Lauf 1* (~12 min). The backlog/matrix component (see below), used live for the first time: at minimum the Erklären and Aufsetzen categories get real cards from the two labs just run; the organizational-lens question ("Wer in Ihrem Haus macht genau das auch?") is asked once, here, not per lab. Session 1 closes with two of the four categories populated — Session 2 (out of this spec's scope) reopens on this same board, cumulatively, and fills the remaining two.

Both labs' client-specific language runs through one hand-edited, build-time seed block of placeholders — `{{Rolle}}` / `{{Branche}}` / `{{Publikum}}` / `{{Firma}}` — the same mechanism used for the matrix seed. The showcase itself stays hardcoded to this client's real documents; genuinely regenerating the showcase from a new client's own material is explicitly a later, unscoped piece of work (see Out of Scope).

**The four steps — boundary and counter-move, used as lab material rather than a warning slide:**

| Step | Boundary | Gegenmittel |
|---|---|---|
| Erklären | Orientation yes; relying on numbers you pass along unverified, no | Verify anything you'd cite at the source; ignore the tool's expressed confidence — it's roughly constant regardless of correctness |
| Aufsetzen | First draft yes, final version no; two people with the same brief get the same text | You always write the final version; supply your own example or it reads generic |
| Aufbereiten | One bounded document yes, twenty no; the answer must be in the text — if it sits between two contradicting sources, this step doesn't apply | Halve the stack and ask twice, checking whether new points appear; for comparisons, swap the order and re-ask |
| Hinterfragen | Generating objections yes; delivering a verdict, no | Never "is this good?" — always "what are the three strongest objections?"; flip the premise and see if it argues the opposite side equally well (a sign it mirrored rather than reasoned) |

**Take-home handout** (downloaded at the close of Session 1, not a numbered content row): a single static `.md` file — recap, 4–6 self-check questions with normalized answer length, 2–3 exercises built from the executive's own Session 0 answers applying Erklären/Aufsetzen, and an explicit "not yet covered" section naming what's coming in Session 2. Content shape is fixed; the exact generation/delivery mechanism (client-side generation vs. a build-time static file) is an open implementation detail, not decided by this spec (see Further Notes).

**Use-case backlog and matrix (shared component, first used at the end of Session 1)**
- One always-editable view — no separate facilitator-edit vs. executive-read-only mode for this component specifically (the read-only rule applies to the rest of the page, but this component doesn't need a mode split to satisfy it, since the facilitator is its only operator in practice).
- Capture via three visually distinct doors feeding one compact, spreadsheet-narrow inventory table: "Aus dem Labor" (lab-debrief captures), "Ideen-Menü" (20–25 supplied use cases grouped by the four fixed categories), "Eigener Use Case" (free entry). A row moves into the backlog by dragging it down (click also works) and is then removed from the inventory.
- Backlog rows expand to reveal Impact/Aufwand sliders, a Persönlich/Organisational tag (a per-card flag, not a separate view or filter), and a repeat/"Abarbeiten" flag.
- The matrix is a real two-axis (Impact × Aufwand) plot with draggable bubbles, two-way synced with each card's sliders. Bubbles sharing a cell fan out into a small ring rather than stacking. The repeat flag renders as a visibly larger bubble. Category colour is currently kept on bubbles (the only categorical dimension available) but is explicitly flagged as not fully settled — no stronger alternative has been proposed or tested.
- Export: a numbered list next to a numbered (not colour-coded) matrix, so a printed/PDF copy stays legible without relying on colour; the same number identifies a use case in both places.
- JSON download is the persistence mechanism — the facilitator downloads it at the end of Session 1 and holds it (not the executive) to carry state into Session 2. This is also the file that, at deploy 2, gets baked into the HTML as a `<script type="application/json" id="matrix-seed">` block for the executive's permanent, read-only, no-file-needed solo revisit.

## Testing Decisions

This is a largely static, content-heavy site; the majority of "correctness" here is prose, layout, and pacing against decisions already locked in the issue tracker, which is not unit-testable. Automated tests should target the small number of genuinely stateful, logic-bearing pieces, and everything else should be verified by hand against the reference prototypes.

**What makes a good test here:** test observable behaviour of the interactive components — the shape of exported JSON, backlog/matrix state transitions, nav-rail position tracking — never internal DOM structure or CSS class names. A test that breaks because a `<div>` became a `<section>` without changing behaviour is a bad test.

**Preferred seam: one state module per interactive component, testable headless (no DOM/browser needed).** Concretely:
- A Session 0 capture module — pure functions taking field edits in and producing the exported JSON shape (`{ person, reifegrad: {n, name, desc}, alltag, ziel }`) out. Test: given a sequence of field edits, the exported payload matches exactly; given no edits, the payload still has the right shape with empty values.
- A backlog/matrix state module — pure functions for adding a card (from any of the three capture doors), moving a card's Impact/Aufwand, toggling the repeat flag and Persönlich/Organisational tag, and producing the export payload (numbered list + numbered matrix positions). Test: fan-out placement for same-cell bubbles is deterministic and reproducible from the same input state; export numbering is stable across re-renders.
- A nav-rail position module — pure function from scroll offset (or a monotonic beat index) to `{done, current, upcoming}` state per rail entry, independent of `IntersectionObserver`/DOM timing. Test: a zero-height-viewport input is handled without corrupting the current position (the "backgrounded tab" bug already found and fixed once — see `issues/15-visual-design-standard.md`).

This is the highest seam available without introducing a framework the project doesn't otherwise need — the goal is one seam per component, not one per DOM node, and definitely not the whole page as a single seam (the page has three genuinely independent pieces of state: Session 0, the backlog/matrix, and rail position).

**Manual verification, not automated:** the keyboard-navigation arrow-key handler (flagged in `issues/20-lesson-level-design-pass.md` as not independently confirmed in-browser); illustration assets against both surfaces per ADR-0001's step 3 (checking for stray grey islands in enclosed holes); voice-navigability of chapter/sub-chapter names (a facilitator can actually say the label and land there in seconds); the two joke gates (`doris`, `askclaude`) actually gate and reset correctly on refresh with no persistence.

**Prior art in this codebase:** none yet — this is the first implementation pass; the prototypes (`prototypes/PROTOTYPE-*.html`) are throwaway design references, not a test suite, and should not be promoted into the build or treated as covering behaviour.
